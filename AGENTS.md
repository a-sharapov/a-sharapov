# AGENTS.md — a-sharapov.com

Сайт-визитка: 3D-стол (Threlte) с визиткой, которая при переходе по меню превращается в лист с контентом из CMS. Стек и конвенции — как в Kuechenly: Bun везде, SvelteKit 3 (SSR, `@sveltejs/adapter-bun` на `Bun.serve`) + Svelte 5, PocketBase, Telegraf, Caddy, Docker. С Astro переехали в октябре 2026 — устройство и ловушки в разделе «SvelteKit и острова».

## Команды

```bash
make dot-env               # .env со сгенерированными секретами (есть — не трогает)
make env                   # .env → env/<сервис>.env по scripts/env/keys.toml
make run                   # dev: proxy, web, bot, cms; затем логи web
make cms-seed              # cms/seed → PocketBase (upsert через REST)
make check                 # как CI: biome, тесты, svelte-check и сборка bot/web, compose, caddy validate, скрипты деплоя и подготовки машины
make check-images          # сборка prod-образов web, bot, cms (в CI — отдельной задачей)
make video                 # клипы 2D-версии из dev-сцены (нужны make run, Chrome, GPU); ONLY=… THEME=…

cd web && bun dev          # Vite dev без Docker (bun --bun vite dev)
cd web && bun test src     # unit-тесты (bun:test)
cd web && bun run check    # svelte-kit sync + svelte-check (типы, и .svelte, и .ts)
cd bot && bun test
bunx biome check --write <files>   # формат и линт (biome.json в корне)
```

Порты dev: web 5701, bot 5702, cms 5703 (только 127.0.0.1); proxy — `PROXY_HTTP_PORT`/`PROXY_HTTPS_PORT` из `.env` (по умолчанию 80/443).

## Архитектура

```
Клиент → proxy (Caddy) → web (SvelteKit SSR, :5701) → cms (PocketBase, :5703)
                                                → bot (Telegraf + bun:sqlite, :5702)
```

- **web** — страницы `routes/(site)/[[locale=locale]]/[...path]` из коллекции `Pages`; i18n из коллекции `i18n` через `t(key)`; заявка: `routes/api/inquiry/+server.ts` → `Inquiries` + уведомление ботом (защита и отказы — раздел «Продакшен»).
- **bot** — `GET /health`, `POST /sendMessage`, `DELETE /user` (Bearer `BOT_SERVICE_TOKEN`); подписчики — `/start`. В prod бот — бинарник `bun build --compile --sourcemap` (`bun run build`, `@docker/bot.prod`: сборка в `oven/bun:1.4.4-alpine`, запуск в `alpine:3.22` с `libstdc++` и `libgcc`, без исходников и `node_modules`): образ 115 МБ (из исходников — 117), ~11 МБ памяти (~13), готов к запросам за 16–33 мс (~41); `--sourcemap` — трассы ошибок ведут в `main.ts:22`, а не в `/$bunfs/root/bot`. В октябре 2026 бинарник убирали: компиляция (~250 МБ, 0.2 с) совпадала со сборкой web на Astro (~1.5 ГБ), и деплой падал на сервере по памяти, а давать серверу больше ресурсов владелец не хочет. Вернули, когда сборка web стала ~1.2 ГБ, на сервере появился swap, а `server.sh` начал собирать образы по очереди (`build`: web, bot, cms) — пики памяти не складываются. Пользователь — uid 1000 через `su-exec` из `entrypoint.sh`; в работе бот занимает ~15 МБ. Типы — встроенный `bun check` (`bun run check` в `check-bot`, `typescript` боту не нужен; в `tsconfig.json` — `"types": ["bun"]`, иначе `bun check` не видит `Bun` и `bun:test`).
- **cms** — миграции `cms/pb_migrations`, сиды `cms/seed`, суперпользователь из `CMS_LOGIN`/`CMS_PASSWORD`.
- Секреты — только `env/*.env` по манифесту `scripts/env/keys.toml`; `.env` и `env/` не коммитятся.

## SvelteKit и острова

- Раскладка `web/`: `src/routes` — маршруты, `src/lib` — остальной код, `static` — публичная статика (при Astro — `public`). Импорты из `src/lib` — subpath imports `#lib/*` из `package.json` (SvelteKit 3 `$lib` не генерирует) **с расширением файла**: `#lib/common/routes.ts`, `#lib/components/@Layout/Header/Header.svelte`, `#lib/common/shell.svelte.ts` — без расширения их не находит TypeScript (Vite и Bun находят); относительные импорты — как раньше, без расширений. SVG, которые компоненты читают текстом (`?raw`), лежат в `src/lib/i/*.svg` и `src/lib/logo.svg` (`#lib/i/mail.svg?raw`, `#lib/logo.svg?raw`), а не в `static`: Vite запрещает импорт из публичного каталога (в dev — предупреждение «Assets in public directory cannot be imported from JavaScript» на каждый запрос, а через `/i/…?raw` SvelteKit отдавал сам файл, и браузер получал `image/svg+xml` вместо JS). В `static/i` — только то, что берётся по адресу (`tick.svg` в CSS, `services/*` маской). Логотип правится в `web/src/lib/logo.svg`.
- Конфиг — только `vite.config.ts` (`sveltekit({ adapter, csrf })`; `svelte.config.js` SvelteKit 3 не читает), `tsconfig.json` наследует `$app/tsconfig` (его пишет `svelte-kit sync` в `node_modules/$app`, `prepare` в `package.json`). Скилл с проверенными фактами по SvelteKit 3 — `sveltekit-3` (`~/.claude/skills`).
- Маршруты: `(site)/+layout.server.ts` — словарь, меню, контакты и узлы графа сайта; зависит только от `params.locale`, поэтому между страницами одной локали не перезапрашивается (с `/` на `/ru/…` — один раз). `(site)/+layout.svelte` — шапка, `main`, подвал, лоадер и остров сцены: макет живёт между страницами, это замена `transition:persist`. `(site)/[[locale=locale]]/[...path]` — страницы CMS (`reroute`: 301, 404, 503 при холодной недоступной CMS), матчер `locale` — `src/params.ts` (`defineParams`). `(site)/+error.svelte` — 404 с планшетом; ошибка 5xx при переходе в браузере — полная перезагрузка, чтобы Caddy показал `fallback.html`. `(site)/dev/scene` — без шапки и подвала (`bare` в данных), `dev/model` — вне группы, без макета; в prod обе — 404. Эндпоинты — `+server.ts`.
- `hooks.server.ts`: `init` — прогрев кэша контента; `handle` — 301 (`REDIRECTS` в `constants.ts`, старые `/en/…`), вставка статичного HTML, `Retry-After: 30` у ответов 503.
- **Острова** (`@UX/Island/Island.svelte`, концепция Astro сохранена по просьбе владельца): `when` — `load` | `visible` | `media` (`query`); код компонента — динамический `import()` из `load`, грузится, когда условие сработало, и остаётся. Два вида. Клиентский (без `html`): на сервере — `fallback`, потом компонент в дереве макета — props реактивны, навигация и контекст общие; так сцена (`media`, `SCENE_MEDIA`) и лаборатория (`load`). С серверной разметкой (`html`): `load` страницы рендерит компонент `render()` из `svelte/server`, разметка вставляется как есть, по условию — `hydrate()` отдельным корнем со снимком props; так форма заявки (`visible`): без JS работает серверная форма, её JS приходит, когда форма у экрана. Обёртка — `div[data-island]` с `display: contents` (`static/css/normalize.css`): форма — flex-элемент колонки; видимость меряется по первому элементу внутри. Клиентские острова на сервере не нужны — `load={import.meta.env.SSR ? undefined : () => import(…)}` (константой в скрипте): иначе серверная сборка тянет чанк сцены с three (+4.3 МБ и 7.6 МБ карт). CSS острова с серверной разметкой подключать статически (`InquiryForm.css` — у `Contacts.svelte`): разметка видна до загрузки чанка.
- **Статичный HTML не сериализуется** (`services/static-html.ts`, тест `static-html.test.ts`): HTML из CMS (с рисунками) и серверная разметка островов идут в данные страницы через `staticHtml(event, html)`. При серверном рендере в данных только метка `<!--as:static:N-->`, а `fillStatic` в `transformPageChunk` ставит настоящий HTML в разметку; в запросах `__data.json` (переходы) приходит сам HTML. `{@html}` при гидратации содержимое не сверяет (в dev сверяет хэш, а он посчитан по той же метке), и серверная разметка остаётся. В JSON данных `<` экранирован (`\u003C`) — метка там не заменяется. На верхнем уровне такого HTML не должно быть пустого комментария `<!---->`: по нему гидратация `{@html}` ищет конец блока.
- Переходы (`Viewer.svelte`): `beforeNavigate` (кроме `willUnload`) — фаза `leaving`, план — по `data-shot` ссылки из `navigation.event.target`, иначе по ссылке с тем же `href`; `onNavigate` возвращает задержку до `_LEAVE_MS` (260 мс) от начала ухода — подмена страницы не раньше, чем погаснет контент (так при Astro оборачивался `loader`); `afterNavigate` (кроме `enter`) — новый план, `epoch += 1`, снять `data-thrown`. В SvelteKit 3 `afterNavigate` при монтировании компонента не вызывается (только `enter` при гидратации) — лениво поднятая сцена его не получает. Программный переход — `goto`. Предзагрузка данных по наведению — `data-sveltekit-preload-data="hover"` на `body` (вместо prefetch Astro).
- `app.html` — `<html lang="ru">` и статичная часть `<head>`: `shell-init.js`, иконки, предзагрузка шрифтов, `/css/*.css`, `og:locale`, `twitter:card`; мета страницы — `@Layout/Head/Head.svelte` в `<svelte:head>`.
- Сборка и запуск — под Bun (`bun --bun vite …` в скриптах `package.json`): SvelteKit 3 при сборке импортирует `src/params.ts` нативно, и под Node цепочка `routes.ts → './constants'` без расширения падает с `ERR_MODULE_NOT_FOUND`. prod — `@sveltejs/adapter-bun` (официальный, `bun ./build`): сервер — `Bun.serve`, статика — его `routes` с `Bun.file`, `precompress: true` — рядом `.br` и `.gz`, у `/_app/immutable/*` — `immutable`. Все пакеты — в `devDependencies`: сервер собран целиком, в образе нет `node_modules` (125 МБ, ~19 МБ памяти в работе). Переменные — как у adapter-node (`HOST`, `PORT`, `BODY_SIZE_LIMIT`, `PROTOCOL_HEADER`, `ADDRESS_HEADER`…), кроме таймаута простоя соединения — `CONNECTION_IDLE_TIMEOUT` (≤ 255 с). `BODY_SIZE_LIMIT=64K` — переменная образа (`maxRequestBodySize`: больше — 413 от `Bun.serve`; Caddy отсекает ещё раньше). Сборка — ~5 с и ~1.2 ГБ памяти.
- **Порядок CSS в prod-сборке другой, чем в dev и при Astro**: Vite раскладывает глобальные CSS компонентов по общим и маршрутным файлам, и у правил равной специфичности меняется победитель. Так было с 404 в плоском режиме: `padding` и `overflow` из `NotFound.css` при Astro перебивал `Sheet.css` (`.sheet:is([data-shot='tablet'])` и `.sheet[data-layout='notfound']` — обе 0,2,0), в prod победил `NotFound.css` — теперь там видимые значения записаны явно. Конфликт равной специфичности снимать явно, а не порядком импортов; проверка — разница вычисленных стилей всех элементов dev и prod-сборки (Playwright, оба размера и обе темы): нормализация минификатором (`0% 0%` и `0px 0px`, градиент `to top` в обратной записи) — не разница.
- Замеры переезда (октябрь 2026, prod, распакованный JS): телефон — 168 КБ (Astro — 91: рантайм роутера и гидратация всей страницы), десктоп — 1875 КБ (Astro — 1807); замер на adapter-bun после удаления портфолио; телефонные скриншоты всех страниц совпали с Astro попиксельно, на десктопе — до шума сцены (`rollJitter`, рекурсия 404).

## Bun

- Всё на Bun 1.4.4: рантайм web и бота, пакеты, тесты (`bun test`), типы бота и неиспользуемые локальные (`bun check`), сервер сайта (`Bun.serve` через adapter-bun), Vite запускается под Bun (`bun --bun vite …`). В коде — встроенные API Bun: файлы — `Bun.file` и `Bun.write` (каталоги создаёт сам), обход каталога — `Bun.Glob`, хэши — `Bun.CryptoHasher`, окружение — `Bun.env`, аргументы — `Bun.argv`, TOML — импорт `.toml`, SQLite — `bun:sqlite`, оболочка — `` Bun.$ ``, пауза — `Bun.sleep`; случайное и сравнение — Web Crypto (`crypto.randomUUID`, `crypto.timingSafeEqual` в Bun глобальный). `node:*` — только где у Bun своего нет: `rename` (атомарная замена файла кэша контента), `mkdirSync` (каталог базы бота), `chmod` (права файлов с секретами), `path.resolve` и `util.parseArgs` (так разбирать `Bun.argv` советует сам Bun).
- Ловушки Bun 1.4.4: `Bun.write(path, data, { mode })` права **не ставит** — файл остаётся 644, поэтому секреты пишутся так: пустой файл, `chmod 600`, затем содержимое (`_writePrivate` в `scripts/env/generate.ts`) — секрет ни мгновения не лежит открытым. `Bun.Glob.scan` по несуществующему каталогу — отказ `ENOENT`, а `Bun.file(<каталог>).exists()` — всегда `false`. Хук `bun test`, возвращающий `` Bun.$`…` `` (ShellPromise) напрямую, висит до таймаута — писать `` async () => void (await Bun.$`…`) ``. `bun check` берёт `types` из `tsconfig.json` (с TS 6 по умолчанию пусто) — нужен `"types": ["bun"]`; у `scripts/` своего tsconfig нет — разовая проверка: `bun check --no-script --types=bun --typeRoots=bot/node_modules/@types --moduleResolution=bundler --strict scripts/…`.
- Переводя скрипт на асинхронные `Bun.file`, сверять поведение со старой версией на одинаковых входных данных (вывод, коды выхода, файлы и их права): так проверены `cms-seed.ts` (dry-run) и `generate.ts` (все команды).
- healthcheck контейнеров в `prod.yml` — `wget` из busybox, не `bun -e`: процесс Bun раз в 30 с дороже на сервере с тесной памятью.

Чашка — тюльпан по фото-референсу в реальных мм (кромка Ø72, `cup.svg`), на столе чашка с ручкой и кофе уменьшены до 0.9 от точки, где ножка стоит на блюдце (`_SCALE` в `Cup.svelte`; кромка Ø65), блюдце Ø110 — как в профиле, пар не масштабируется (ray-march в осях объёма разрядил бы струйку); кофе — по фото-референсу (вид сверху), процедурный TSL-материал (`Coffee/nodes.ts`): большая часть глади — тёмный кофе (`_POOL`, смещено к зрителю), крема — золотистый серп у стенки, толстый с дальней стороны (чёрные пузыри-поры трёх размеров по шуму Уорли), тонкий у ближней (светлая пена); объём — смещение вершин сетки `RingGeometry`: от края окна к стенке крема растёт экспоненциально (`_GROWTH`, вогнутая чаша, не вал — у стенки 1–2 мм) и `bumpMap` той же высоты в см с масштабом 1; гладь кофе без лака (иначе сверху в ней зеркалом отражается потолочное окно), пар — еле заметная вьющаяся струйка с шумовым хаосом фазы, размаха и сноса (плотность — `mood.steam`: днём 0.6, ночью 0.1 и приглушённо-серый), объёмная: ray-march в цилиндре над гладью (`Steam/nodes.ts`, 28 шагов со сдвигом по пикселю и кадру — ступени сглаживает TRAA), струйка — трубка вокруг пространственной кривой (`Steam/axis.ts`: сбоку змейка, сверху завиток; ось с хаосом считается на CPU раз в кадр в `uniformArray`), шум волокон — трилинейные выборки тайлящейся 3D-текстуры (`Steam/noise.ts`; MaterialX-шум в каждой выборке стоил > 1 мс GPU); плотность нормирована на толщину и на синус угла луча к оси — с любого ракурса струйка одной плотности; сверху (только при крутом взгляде вниз) над гладью ещё рассеянная дымка; пар — на `FLAT_LAYER`, камера отражения его не видит; пар виден на всех планах (в `Scene.svelte` прозрачность — `mood.steam`, без привязки к общему плану); самолётик — 1:1 по исходному `paper_plane.glb` (вершины → `paper-plane.svg`) в масштабе исходной сцены. Планшет 11" (`tablet.svg`; не Apple: круговые углы, платиновый корпус) лежит экраном вверх сверху стопки за визиткой, на 404 подаётся в центр стола и загорается; резюме — ровная пачка листов A4 со скрепкой (`cv.svg`, `Resume.svelte`; скрепка по фото: квадратный ближний загиб, дальние — острые шевроны; у правого края листа, над краем места под фото; платина темнее общей — `_CLIP_TINT` в `Resume.svelte`, светлая терялась на белом листе) — низ стопки за визиткой, первая страница — абстрактная вёрстка (`drawCvPage`) той же сетки, что текст CV: полоски стоят по замеру DOM-листа в мм (1440 × 900, лист 210 мм = его ширина; `_CV`); меняя сетку страницы, перерисовать и вёрстку листа. На основании лампы — кнопка: платиновый ободок и дубовый купол. В лаборатории модель всегда на поворотном столе (`?spin=0` — стоп), камера крутится мышью.

## Облегчённая 2D-версия (видео)

Та же сцена без 3D (просьба владельца): композиция и планы те же, но вместо WebGPU — записанные из настоящей сцены клипы WebM. Только десктоп (`SCENE_MEDIA`), телефоны по-прежнему получают упрощённую версию без сцены.

- **Режим** — `shell.scene` (`'3d' | 'video'`), выбор хранится в `AS_scene` (`STORAGE.scene`), `shell-init.js` до первой отрисовки ставит `html[data-scene='video']`. Переключатель в шапке — `@UX/SceneSwitcher` (куб: в 2D рёбра глубины сматываются `stroke-dashoffset`, передняя грань съезжает в центр; предпросмотр при наведении — `GlyphPreview`, черта под иконкой — когда включено 3D; на телефоне скрыт, как звук). Если сцена через 4 с после начала загрузки всё ещё в `boot`, лоадер предлагает облегчённую версию (`SceneLoader`, `scene.lite.*`; сам гаснет, когда фаза сменилась). Макет оборачивает остров сцены в `{#key shell.scene}`: переключение размонтирует Canvas Threlte и грузит `@Viewer/Video/VideoViewer.svelte` (и обратно), без перезагрузки страницы. В видеорежиме кнопки звука нет: события звука привязаны к ригу сцены.
- **Выбор режима на слабом устройстве** (просьба владельца): если выбора ещё нет (`AS_scene` пуст), окно — десктопное (`SCENE_MEDIA`) и устройство слабое, вместо загрузки сцены лоадер показывает две узкие бумажные карточки — «2D-версия» (отмечена «Рекомендую»: красная черта сверху, как маркер пункта меню) и «3D-сцена» (`@UX/SceneChoice`, остров `load` внутри `SceneLoader`: чанк с карточками и рисунками качают только слабые устройства; тексты — i18n `scene.choice.*`). Клик — `chooseScene`: выбор сохраняется, как у переключателя в шапке, и больше не спрашивается. Слабость решается синхронно при загрузке модуля `shell.svelte.ts` (до гидратации, поэтому остров сцены не успевает начать загрузку): `probeDevice` (`common/graphics.ts`, тест `graphics.test.ts` на настоящих строках рендереров) создаёт контекст WebGL с `failIfMajorPerformanceCaveat` и `powerPreference: 'high-performance'` (на ноутбуке с двумя видеокартами — дискретная), читает `UNMASKED_RENDERER_WEBGL` и сразу отпускает контекст (~30 мс на холодном процессе GPU, только когда выбора нет). `graphicsOf`: программный рендер (SwiftShader, llvmpipe, Basic Render) или контекст только без `failIfMajorPerformanceCaveat` — `software`; NVIDIA, Intel Arc A/B, остальные Radeon — `discrete`; Apple M и Safari `Apple GPU`, Intel Arc встроенная (Meteor/Lunar Lake), Radeon 660M–890M и 8060S, Snapdragon X — `modern`; Intel HD/UHD/Iris/Iris Xe, Radeon «… Graphics» и Vega (APU), Radeon 610M/740M, Mali, Adreno, PowerVR — `integrated`. Слабое (`weakDevice`) — `software` и `integrated` всегда, `modern` и неопознанное — при ≤ 4 ядрах (`hardwareConcurrency`) или ≤ 4 ГБ (`deviceMemory`, только Chromium), дискретная — никогда (это «старое устройство без дискретной видеокарты» из просьбы). Пока идёт выбор: `html[data-scene='choose']`, остров сцены без загрузчика (ключ `mode` в макете), `main` — `inert` (Tab сразу ведёт к карточкам), подпись лоадера стоит дописанной, бегущий маркер скрыт; после клика блок сворачивается (`grid-template-rows` 1fr → 0fr), подпись съезжает к центру и снова пишется — грузится выбранный режим. Сторож «15 с в `boot` → `failed`» в `shell-init.js` выбор не считает и заводится заново от клика (`window.__asWatch`), предложение облегчённой версии через 4 с (`SceneLoader`) — тоже от клика. Рисунки карточек (`SceneChoice/art/video.svg`, `3d.svg`; 120 × 76) — тем же генератором, что пиктограммы «Услуг» (он вне репозитория, см. «Услуги» в «Ловушках»): у 3D — куб с красной орбитой камеры (кольцо проходит перед кубом и прячется за ним, наконечник — в плоскости экрана), у видео — кадры веером, на переднем тот же куб плоским рисунком, «плей» и красная полоса прогресса. Проверка без слабой машины — dev-флаг `?gpu=weak` (показать выбор, даже если он сохранён) и `?gpu=strong`; настоящий слабый путь — Chrome без флагов GPU (SwiftShader) показывает выбор сам. Ниже 36rem по высоте подпись над карточками скрыта, ещё ниже лоадер прокручивается (`place-content: safe center`).
- **Плеер** (`VideoViewer.svelte`, логика — `video.ts`, тест `video.test.ts`) рисует тот же `.viewer[data-phase]` с теми же фазами (boot · loaded · moving · settled · leaving) и теми же `beforeNavigate`/`onNavigate`/`afterNavigate`, поэтому лоадер, проявление контента, шапка и прозрачный лист работают без изменений. Два `<video>`: новый клип проявляется поверх старого (без провала яркости посередине), шов 240 мс прячет расхождение пара и пылинок между клипами. Клип грузится целиком (`fetch` → blob URL) — переход не может застрять на середине; после `settled` подгружаются клипы со страницы, где стоит зритель. Маршрут (`routeOf`): прямой клип; от визитки — сначала `card-in`; пара без клипа — через главную; иначе (например, на 404) — растворение петель за 600 мс. Новый переход во время клипа — текущий доигрывается ×4, затем следующий. Контент проявляется на метке `reveal` — в записи это момент, когда сцена перешла в `settled`. Смена темы — тот же клип другой темы с того же места (500 мс). Визитка: прозрачная кнопка над её местом (`card.spot`), `card-out` → петля `card` с невидимыми ссылками поверх строк оборота (`card.links` по порядку контактов с иконками — `cardLinks`; изменился список контактов — ссылок нет, а не ведут не туда) → клик мимо или Esc — `card-in`. Бросок самолётика после заявки — клип `toss`: на метке `thrown` — `html[data-thrown]`, на `away` — `goto('/')`. `prefers-reduced-motion` — без клипов (растворение петель), петли стоят на первом кадре. Видео не загрузилось — через 15 с срабатывает обычный `data-scene='failed'`, загрузилось позже — плеер возвращает `video`.
- **Кадрирование** (`fitVideo`): запись — кадр R = 1600 × 850 CSS при плотности 2.4 (3840 × 2040; плотность сцены `QUALITY.*.dpr` на время записи закреплена — `[2.4, 2.4]`: с потолком 1.75 «4K» растянут, а с нижней границей 1 адаптивная плотность под часами Playwright сбрасывала её до 1 — кадр идёт 32 мс поддельного времени, скрипт кадра по поддельному `performance.now` ~0, и `nextDpr` считает, что не успевает GPU; так первые записи «4K» были растянутым кадром 1600 × 850 и выглядели мутными при любом кодировании, а замер плотности при загрузке этого не видел — сброс шёл в переходах). Видео масштабируется «cover», лишнее по высоте режется сначала снизу, чтобы верх листа остался под шапкой. Листы DOM в видеорежиме берут прямоугольник лица из видео (`faces` манифеста, пересечённый с полосой между шапкой и подвалом) через `--video-face-<spot>` на `<html>` (`Sheet.css`), а не свой CSS-размер 3D-режима: текст всегда на бумаге видео, но размер листа зависит от окна иначе, чем в 3D (поля шапки и подвала в rem, а видео масштабируется целиком). Высота R подобрана под 1440 × 900: там разворот «Услуг» 1025 × 727 против 1024 × 726 в 3D и не прокручивается (с R = 1360 × 720 он был на 27 px ниже и уходил в прокрутку); выше окна — листы крупнее, чем в 3D; ниже 850 — меньше, и верх бумаги подходит к шапке, а лист DOM всё равно начинается под ней. Формат R 1.88 — окна браузера обычно 1.75–2.05. Кадр чуть меньше ролика (до `SNAP` = 3 %) выводится пиксель в пиксель: масштаб поднимается до размера ролика, а сдвиг округляется до целых физических пикселей (`fitVideo` с `display` — вариант и плотность экрана; `_snap`, `_pixel`). Иначе браузер пересэмплирует, например 2048 → 2033 px со сдвигом на полпикселя на 1920 × 1080, и резкий кадр мылится. Так выводятся 1920 × 1080 и 1536 × 864 при 125 % (оба — 1920 физических пикселей, вариант `hd`): листы на 0.7 % крупнее, чем по «cover»; проверка — скриншот против кадра файла: PSNR 49 дБ без сдвига, 30 дБ со сдвигом на пиксель.
- **Файлы**: `web/static/video/<uhd|hd>/<light|dark>/` — петли страниц `<spot>.webm` (6 с; шов сделан при кодировании — последняя секунда растворяется в первой, `xfade`), переходы `<from>-<to>.webm` между главной, CV, «Услугами» и контактами и с 404 на них (на 404 — растворение), `card-out`, `card`, `card-in`, `toss`; манифест `@Viewer/Video/clips.json` (генерируется): размеры, `faces`, `card`, длительности и метки, `versions` — начало sha256 файла, уходит в адрес `?v=` (кэш `/video/*` — как у остальной статики, см. «Публичная статика без хеша»). Два варианта из одних кадров (просьба владельца — 4K, но облегчённая версия нужна и слабым машинам): `uhd` 3840 × 2040 (VP9 CRF 26) и `hd` 2048 × 1088 (CRF 20, уменьшение lanczos; 2048, а не 1920 — кадр в окне 1920 × 1080 шириной 2033 и не растягивается); плеер берёт `uhd`, если кадр на экране шире `UHD_FROM` = 2200 физических пикселей (`variantFor`: ширина кадра × `devicePixelRatio` — Retina, 2K и 4K), иначе `hd`, и не меняет его до перезагрузки. **Зерно не записывается** (владелец: «мутно»): попиксельный шум кодек не держит — в `hd` он стирался и кадр выглядел восковым, в 4K на Retina превращался в пятна, а сам весил больше всего. Запись идёт с `GRAIN.gain` = 0 (`lens/film.ts`, ставится до сборки конвейера): шум зерна обнуляется, а его сдвиг тона (`mean − color` × `strength`) остаётся. Шум возвращает плеер — `.grain` поверх кадра: неподвижная плитка белого шума 256 физических пикселей (`grainPixels`, без масштабирования — `image-rendering: pixelated`, размер фона 256 / `devicePixelRatio`), `mix-blend-mode: soft-light` (как и зерно сцены — сильнее в средних тонах), сила `--video-grain` подобрана замером высоких частот на ровном столе против 3D (СКО разности с размытием σ 1.2): днём 0.16 (стол 3.2 против 3.2, чашка 2.8 против 2.8), вечером 0.03 (чашка 1.0 против 0.86; вдвое слабее вместе с зерном сцены — 0.08 и 0.015: стол днём 1.66 против 1.67 в 3D; при 0.05 — вдвое сильнее 3D: soft-light в тёмных тонах сильнее зерна сцены, оно в линейном пространстве; стол вечером и без зерна не глаже, чем в 3D); перемерять после каждой перезаписи — первый подбор шёл на размытых клипах. `.frame` — `isolation: isolate`: иначе видео с `z-index: 1` оказывалось над слоем зерна. Без шума кодирование почти без потерь: зерно весило больше всего остального кадра. 4K — CRF 26, а не 18 (просьба владельца — легче): самый тяжёлый переход («главная → «Услуги»») 3.9 → 2.6 МБ, весь 4K −34 %, а при показе на Retina 1440 × 900 наброски скетчбука, точки сетки и рукописный текст на глаз не отличаются (PSNR к CRF 18 — 53.9 дБ); CRF 30 — ещё −25 % (52.6 дБ). **Ступени на тёмных градиентах** (вечерний лист CV, видно при повышенном контрасте): это 8-битный YUV, не CRF — при CRF 18 те же ступени, исходный PNG гладкий; 10-битный VP9 (`-profile:v 2`, `yuv420p10le`) их убирает (низкочастотная ошибка p99 2.9 → 0.8 из 255) и легче на 13 % при том же CRF, но не включён: поддержка VP9 profile 2 в Safari не проверена — нужна проверка `canPlayType`/`mediaCapabilities` и запасной 8-битный вариант. **Цвет**: перевод в YUV по BT.709 (`out_color_matrix=bt709`) и метки в файле (`setparams`: primaries/matrix BT.709, передаточная sRGB, ограниченный диапазон) — без них ffmpeg переводил по BT.601, а Chrome декодировал HD как BT.709, и насыщенные цвета съезжали (кадр в Chrome против исходника: PSNR 47.6 → 49.7). Ключевой кадр раз в 2 с, 31.25 кадра/с. Вес (CRF 26/20): `uhd` — 67.3 МБ на обе темы (петля в среднем 0.4–0.5 МБ, переход 1.6–1.7 МБ, до 2.7), `hd` — 32.2 МБ (петля 0.2–0.26 МБ, переход 0.7–0.8 МБ). Посетитель качает петлю своей страницы и после `settled` — 3–4 перехода с неё: главная целиком — 6.4 МБ в 4K и 3.1 МБ в `hd`.
- **Запись** — `make video` (`scripts/video/record.ts`, свой `package.json` с `playwright-core`; нужен запущенный dev-стек с сидами CMS, Chrome и настоящий GPU — флаги из «Ловушек»), `ONLY=intro,intro-resume` — переснять только эти клипы (манифест сливается), `THEME=light`. Каждая сессия — свежая страница: время сцены ведут часы Playwright (`page.clock`, пауза, шаг 32 мс — это два кадра поддельного rAF, сетка 16 мс), кадр — `Page.captureScreenshot` с `clip.scale` = плотности (без него CDP отдаёт CSS-пиксели) и `optimizeForSpeed` (PNG 4K ~7 МБ, поэтому кадры — на диске, `~/.cache/a-sharapov-video`, а не в `/tmp` — на Fedora это tmpfs в памяти; кодирование идёт одной очередью параллельно со съёмкой, каталог кадров удаляется после кодирования), DOM скрыт (`visibility`, раскладка листа для `stageFit` остаётся). Детерминизм: `Math.random` подменён — у `rollJitter` постоянные доли (инструменты ложатся одинаково во всех клипах, иначе стык клипа и петли сдвигал бы ручку), первый порыв листвы гобо — на 8 с после монтирования, следующий — через 40 с, запись начинается через 12.5 с после монтирования; выдержка смаза `MOTION.exposure` = 1/62.5 (180° при 31.25 кадра/с). Конец клипа — `settled` и `rig.still` 12 кадров подряд. Визитка — синтетические `pointerdown`/`pointerup`/`click` по канвасу (без наведения и параллакса камеры); строки ссылок оборота ищутся сканированием `pointermove` по курсору `pointer`: Threlte обрабатывает только первое `pointermove` за кадр, остальные — в rAF, поэтому на время сканирования rAF подменён очередью, которая выполняется после каждого движения (синхронный rAF ломал цепочку `raf` Svelte — твин переворота замирал, и Esc не возвращал визитку). Проверка стыков: первый кадр клипа против кадра петли — разница на уровне межкадрового шума (пар, пылинки, TRAA). Переснимать после любой видимой правки сцены, текста визитки, контактов, вёрстки листа CV; полная запись — ~50 мин. Пока идёт запись, `web/src` не править: макет импортирует плеер динамически, и правка любого модуля макета (в том числе `VideoViewer.svelte`) — HMR посреди съёмки. Манифест `clips.json` во время записи должен существовать: Vite в dev разбирает импорты плеера и при каждом заходе на страницу, и без файла показывает окно ошибки `video.ts` поверх сцены — так в октябре 2026 испортилась вся полная запись (окно в 31 клипе из 35, сессия зависла). Поэтому запись создаёт пустой манифест при старте, сессия с `vite-error-overlay` на странице падает, кадр без ответа 60 с (`FRAME_DEADLINE_MS`) — тоже; удалять `clips.json` перед полной перезаписью не нужно (манифест сливается, `frame` и `video` берутся из записи).

## Конвенции (Kuechenly)

- `pipe`/`reduce`, `.then(_handle, _catch)` + `pipe`; без early return и блочных тел ради `return` — выражения, тернарии, lookup map вместо `if`.
- `if`, тело которого — только `return`, пишется одной строкой без фигурных скобок (правило владельца): `if (page === undefined) return new Response(null, _UNAVAILABLE);`, а не блок из трёх строк. Не влезает в 80 знаков — вынести значение в константу, а не переносить строку. В `load` SvelteKit ранний выход — бросающие `redirect`/`error` из `@sveltejs/kit`, `return` не нужен, правило то же: `if (shape && 'redirect' in shape) redirect(301, shape.redirect);` одной строкой.
- `export var` и стрелочные функции; сервисы — `define*Service` + default export. **Деструктуризация массивов — только индексным объектом** (`const { 0: a, 1: b } = pair`, `({ 0: x, 1: y }) => …`, и в колбэках `Object.entries`, и в TSL `Fn`), никогда `[a, b]` — важное правило владельца; разбор строки с остатком — через индекс и `slice`.
- UI-строки — только `t(key)` из CMS; CSS — без `:global` во внешних файлах, размеры в rem/em; иконки в кнопках — SVG.
- Код без комментариев (по просьбе владельца): решения, замеры и ловушки — в этом файле. Остаются только директивы (`@ts-check`, `/// <reference>`, `biome-ignore`, `svelte-ignore`, `# syntax=`) и справка `## …` у целей Makefile (её читает `make help`). Идентификаторы — на английском.
- После правки логики — тесты затронутой зоны и `bun run check`; временные артефакты — вне репозитория.
- Мёртвый код искать `bunx knip@5` (в `web` и `bot`), неиспользуемые локальные — `bun check --no-script --noUnusedLocals` (в `web` проверяет только `.ts`, `.svelte` — `svelte-check`). Точки входа SvelteKit 3 knip сам не находит (нет `svelte.config.js`) — они в `web/knip.json`: маршруты, `hooks.server.ts`, `params.ts`, тесты; `$app/*` — виртуальные модули. Ложные срабатывания: `static/js/shell-init.js` (подключён тегом в `app.html`), импорты `#lib/i/*.svg?raw`, совпадения имён с TSL (`length`, `smoothstep`), экспорты, нужные только тестам (`roomPending`), и константы-«ручки», которые используются внутри своего модуля и упоминаются здесь по имени, — их не трогать: снимать `export` пришлось бы с переименованием в `_…`. `static/service-worker.js` ни откуда не подключён намеренно: это «самоликвидатор» воркера старого сайта — браузер сам запрашивает его при проверке обновлений, а он чистит кэши и снимает регистрацию. Звуки `static/sounds/*` упомянуты в манифесте `samples.ts` по именам без расширения.

## Продакшен: безопасность и отказы

- **Серверные переменные — только `Bun.env` в рантайме** (`services/env.ts`, `SERVER_ENV`: `PB_URL`, `BOT_URL`, `BOT_SERVICE_TOKEN`): `import.meta.env.<ИМЯ>` Vite вписывает в сборку значением на момент `bun run build` (при Astro локальная сборка запекала dev-токен бота в `dist`, а в Docker сборка идёт без окружения — `env_file` только при запуске). `$env/*` SvelteKit не нужны: `bun test` их не знает. Тест `env.test.ts` не пускает `import.meta.env.*` кроме встроенных Vite (`DEV`, `PROD`, `SSR`, `MODE`, `BASE_URL`) и `VITE_…`. Без токена в проде — предупреждение в журнале при старте.
- Размер тела запроса — 64 КБ: `BODY_SIZE_LIMIT=64K` у adapter-bun (`maxRequestBodySize` `Bun.serve`, ответ 413; у Node-адаптера Astro по умолчанию был 1 ГиБ при лимите контейнера 512 МБ) и `request_body /api/inquiry` в Caddy (`routes.web.caddy`; шире `/api/*` нельзя — в dev там же админка CMS `/api/cms/` с загрузкой файлов).
- `redirects.html.caddy`: путь до `.html` начинается с буквы или цифры — прежнее `^/(.*)\.html$` давало открытый редирект (`/%5Cevil.example.html` → `/\evil.example`, браузер читает как `//evil.example`).
- **Заявка** (`routes/api/inquiry/+server.ts`): `Origin` — свой (`SITE_ORIGIN` или адрес запроса), иначе 403; ещё раньше форму с чужим `Origin` отсекает CSRF-проверка SvelteKit (в prod всегда включена, `csrf.trustedOrigins` — `SITE_ORIGIN`) — текстовым 403, форма показывает ошибку; адрес запроса adapter-bun собирает из `Host` (его передаёт Caddy) и протокола `https` по умолчанию (`PROTOCOL_HEADER` не задан) — локально по `http://127.0.0.1` форма получит 403, проверять за proxy или с `PROTOCOL_HEADER=x-forwarded-proto` и этим заголовком; частота — в памяти процесса по хэшу IP с солью процесса (`services/rate-limit.ts`: 5 за 10 мин с адреса и 60 на всех, затем 429 с `Retry-After`; IP — первый в `X-Forwarded-For`, его ставит Caddy, входящий он не доверяет); согласие обязательно и на сервере (`terms=yes` → `consent`, поле `Inquiries.consent` — обязательный bool, миграция `1791929680_…`). Форма работает и без JS (`method="post" action="/api/inquiry"`): запрос с `Accept: text/html` получает 303 на страницу (`page`, только свой путь) с `?sent` — форма сразу рисуется в состоянии «отправлено» (`sent`, `INQUIRY_SENT_QUERY`).
- **Кэш контента и отказ CMS** (`common/cache.ts`, `services/content.ts`, тест `cache.test.ts`): TTL 30 с, по схеме «устаревшее — сразу, обновление — в фоне»: просроченная запись отдаётся без ожидания и запускает одну фоновую загрузку (одновременные запросы ключа сливаются в одну); не удалась — запись живёт дальше, повтор не раньше чем через TTL, в журнал одна строка на ключ (`content.cache <ключ>:` — и сбои загрузки, и сбои файлов). Стратегия — `CACHE_STRATEGY` (манифест, web): **`file` по умолчанию** — память процесса плюс файлы `.cache/content/<ключ>.json` (в prod — том `web_cache`, каталог создаёт `@docker/web.prod` с владельцем `bun`: файловая система контейнера только для чтения), `memory` — только память. Запись в файл — после каждой удачной загрузки, атомарно (временный файл и `rename`); файл ключа читается один раз за жизнь процесса, когда ключа нет в памяти, и считается **устаревшим**: отдаётся сразу, а свежее грузится в фоне — данные прошлой версии кода живут миллисекунды, а перезапуск и деплой при лежащей CMS не роняют сайт. Без файла ждёт CMS только холодный ключ. Страницы — один ключ `pages:<локаль>`: список опубликованных (гости и так видят только `published = true` — правило коллекции), из него же `find` и меню; пустой список — недоступность, не кэшируется (иначе прогрев при старте на пустой CMS держал бы 404 ещё 30 с после сидов, а при живом кэше остаётся прежний список); несуществующий адрес (`/wp-admin` от сканеров) в CMS не ходит и отвечает 404. При старте процесса список, словарь и контакты прогреваются. Запросы к PocketBase — с дедлайном 5 с (`beforeSend` в `pb.ts`). Холодный ключ и CMS недоступна — `find` отказывает, страница отвечает 503 с `Retry-After: 30` (раньше сбой CMS выглядел как 404 и мог выкинуть страницы из индекса), Caddy подменяет 5xx страниц на `fallback.html` (`handle_response` в `routes.web.caddy`, `no-store`), ответы `/api/*` — нет: форма разбирает их JSON. Правки в CMS видны через 30 с и один запрос (первый после TTL ещё получает старое). Проверка: прогреть, `docker pause a-sharapov_cms` дольше TTL — страницы отвечают за ~10 мс, через 5 с в журнале по строке на ключ; затем пересоздать web — страницы по-прежнему 200 из файлов (проверено на prod-образе с `--read-only` и `--cap-drop ALL`, первый запрос 0.26 с). Проверка связи с CMS в `pb.ts` — фоновая: прежде импорт ждал её (4 попытки, ~29 с) и первый запрос при лежащей CMS висел, хотя клиент создаётся в любом случае.
- **Без JS и при отказе сцены**: `<noscript>` кладёт маркер `.no-js`, `shell-init.js` через 15 с после первой загрузки ставит `html[data-scene='failed']`, если сцена всё ещё в фазе `boot` (на десктопном размере); тогда контент, шапка и подвал видны, лоадер и холст скрыты, на главной — бумажная визитка и вводный абзац, как в упрощённой версии (стили `.paper-card` — общие, показ — в плоском медиазапросе и в запасном режиме). `<html>` переходы SvelteKit не подменяют — флаг держится сам, догрузившаяся сцена снимает его (`_recover` в `Viewer.svelte`); в фазе `boot` до загрузки острова — его серверная заглушка `.viewer[data-phase='boot']`. Плашка вводного абзаца при фокусе с клавиатуры — только в режиме сцены: в плоском режиме она давала подложку и тень тексту под визиткой.
- Адреса: `load` страницы — `reroute` (`routes.ts`): один сегмент без локали (`/cv`) — 301 на `/ru/cv`, лишние сегменты (`/ru/cv/x`) — 404 (раньше 200 с canonical на самого себя — дубли); `/ru/cv/` — 308 на `/ru/cv` (`trailingSlash` SvelteKit по умолчанию `never`; при Astro отвечал 200); canonical — из `hrefFor` по странице из CMS, не по пути запроса.
- Заголовки (`headers.secure.caddy`): CSP — всё своё (`'self'`), `'unsafe-inline'` для скриптов и стилей (встроенный скрипт запуска SvelteKit с данными страницы, `style` у Svelte), `blob:` для воркеров и медиа; `Permissions-Policy` без камеры, микрофона, геолокации, датчиков, оплаты и `browsing-topics`; `X-XSS-Protection` убран (устарел), `meta generator` — тоже. Подключая внешний ресурс (шрифт, CDN, аналитику), править CSP и политику данных; проверка — обход страниц в Chrome с заголовком CSP через `route` Playwright и сбор `securitypolicyviolation`.

## CI/CD

- **CI** (`.github/workflows/ci.yml`): push и PR в `master`, вручную. Задачи — цели Makefile, чтобы локально было то же самое: `lint` (`check-lint`: `biome ci` всего репозитория, валят только ошибки), `web` (`check-web`: тесты, `svelte-check`, сборка), `bot`, `infra` (`check-compose`, `check-proxy`, `check-deploy`: shellcheck скриптов деплоя и подготовки машины, тест `seed-targets.test.sh`), `images` (`check-images`: три prod-образа). Bun в CI — `BUN_VERSION` 1.4.4, как в `@docker/*` и `BUN_VERSION` скриптов подготовки сервера: меняя одно, менять и остальное. `svelte-check` — с порогом `error`, ошибок нет (типы TSL в `ReflectiveDesk` поправлены: `Node<'float'>`, `Node<'vec2'>`, камера кадра может быть `null`), остаются давние предупреждения `state_referenced_locally`. Без `.env` цели работают на значениях манифеста (`compose-check.sh` берёт `.env.example`). Проверка workflow — actionlint через stdin: `docker run -i --rm rhysd/actionlint:1.7.7 -stdin-filename .github/workflows/ci.yml - < .github/workflows/ci.yml` (смонтированный репозиторий контейнер под SELinux не читает).
- **Деплой** (`.github/workflows/deploy.yml`) — вручную: Actions → Deploy → Run workflow на `master`. `verify` пускает дальше, только если у этого коммита есть зелёный CI от push. Настройки — в окружении GitHub `production`: секрет `DEPLOY_SSH_KEY` (закрытый ключ), переменные `DEPLOY_HOST`, `DEPLOY_HOST_KEY` (ключ хоста `ssh-ed25519 AAAA…` из таблицы скрипта подготовки — шаг `Prepare SSH` сам допишет перед ним `DEPLOY_HOST` или `[DEPLOY_HOST]:DEPLOY_PORT` — либо готовая строка known_hosts из `ssh-keyscan -t ed25519 <host>`, отпечаток сверить с сервером), `DEPLOY_USER`, `DEPLOY_PATH`, `DEPLOY_URL` (`https://a-sharapov.com`), `DEPLOY_PORT` (необязательно, 22); пустые перечисляет шаг `Check settings`. `Prepare SSH` проверяет, что `DEPLOY_HOST_KEY` читается как ключ (`ssh-keygen -F` по адресу → `ssh-keygen -lf`), и печатает тип и отпечаток для сверки: обрезанный ключ или перенос строки внутри (частое при копировании длинной строки из терминала) ssh молча пропускает и падает с загадочным «No ED25519 host key is known for <адрес> and you have requested strict checking» — так было на первом запуске для 68.183.12.170 (Ubuntu 22.04, OpenSSH 8.9; ED25519 `SHA256:L+zXNy4AYLj3KLLkcYlleQXPGWOsNoHuPiXXIEsjUu8`). Ключ любого типа (RSA, ECDSA, ED25519) подходит: клиент сам предпочитает алгоритм известного ключа. Второй запуск упал так же из-за `DEPLOY_HOST` = `68.183.12.170\r\n` (перевод строки, вставленный в поле переменной): `known_hosts` записывался с адресом `…170\r`, а ssh обрезает пробелы в своём конфиге и ищет чистый адрес. Поэтому `Check settings` теперь обрезает пробелы и переводы строк по краям у всех `DEPLOY_*` (у `DEPLOY_HOST_KEY` — построчно), предупреждает об этом, на пробел внутри однострочного значения — ошибка, и передаёт очищенные значения дальше через `$GITHUB_ENV`. Сырые значения в `env:` задачи названы `VAR_DEPLOY_*`: `env:` уровня задачи перекрывает `$GITHUB_ENV`, и с теми же именами очистка бы не подействовала. Перезапуск (Re-run) неудачного Deploy берёт тот же коммит и тот же workflow — исправления workflow проверять новым запуском (Run workflow). Раннер собирает git bundle проверенного коммита, кладёт его в `$DEPLOY_PATH/.deploy/` и выполняет `scripts/deploy/receive.sh` из этого же коммита через `ssh deploy "bash -s -- …" < …`; в конце — `$DEPLOY_URL/api/health` снаружи.
- `receive.sh`: `chown` каталогов `cms/pb_migrations` и `cms/pb_hooks` обратно пользователю деплоя (контейнер CMS делает их root, и git не смог бы заменить файлы; через `alpine:3.22` с `:z`, только если они чужие), `checkout -f -B master <sha>` — `.env`, `env/`, `cms/pb_data`, `bot/data` не отслеживаются и не трогаются, — затем `server.sh` с `DEPLOY_REF`/`DEPLOY_PREVIOUS_REF`. Предыдущая версия — последний **успешный** деплой из `.deploy/deployed` (пишет `server.sh` в конце), а не HEAD: неудачная попытка (нет `.env`, сборка упала) уже переключила checkout, и с HEAD первый настоящий деплой пропустил бы сиды, а откат «вернул» бы тот же коммит.
- `server.sh`: `.env` есть и закрыт (600) → `make env`, `env-check` (prod) → сборка образов по очереди (`build`: web, bot, cms — пики памяти не складываются; до этого места любой сбой оставляет стек как был) → `up -d web bot cms`, `up -d proxy` (пересоздаётся, только если изменилось его описание в `prod.yml`) и `caddy reload` (конфиг смонтирован) → ожидание `healthy` у `a-sharapov_web` (healthcheck в `prod.yml` → `/api/health`: web отвечает и CMS жива; `start_interval` 2 с; 60 × 2 с) → сиды CMS только изменённых в релизе файлов (`seed-targets.sh`: `cms/seed/i18n` → `i18n`, `pages.json` → `pages`, `contacts.json` → `contacts`; на первом деплое — все; `make cms-seed ONLY=…` по IP CMS во внутренней сети; сбой сидов — предупреждение, не откат) → smoke через proxy (`curl -k --resolve <DOMAIN>:<PROXY_HTTPS_PORT>:127.0.0.1` — главная и `/api/health`; повторы до `DEPLOY_SMOKE_RETRIES` × 2 с, по умолчанию 60 с: только что пересозданный Caddy ещё не загрузил сертификат из тома `caddy_data` и отвечает на TLS `tlsv1 alert internal error` — так 18 октября упал первый деплой, запрос ушёл через 0.8 с после старта proxy; ответ health сверяется без `grep -q` в конвейере, см. ловушку `pipefail` в «Подготовке сервера») → запись `.deploy/deployed`, `docker image prune -f`. Сиды — до smoke: на новом сервере CMS пустая, и главная до сидов отвечает 404. Сбой после `up` (контейнеры, `healthy`, smoke) — **откат**: checkout предыдущего коммита, сборка (слои в кэше), `up`, `healthy`, и задача в Actions красная с причиной. Миграции CMS откат не отменяет: миграция должна работать и с предыдущей версией кода. Пока web пересоздаётся, Caddy не трогается и отдаёт `fallback.html`.
- Правки в CMS-админке прода перезаписываются только сидом того же файла в следующем релизе — источник текстов по-прежнему `cms/seed`.
- **Подготовка сервера** — `scripts/setup/ubuntu.sh` и `scripts/setup/fedora.sh` (root). Каждый — один самодостаточный файл (просьба владельца: залить на сервер без репозитория — `scp` или `ssh root@host 'bash -s' < …`), поэтому общие части в них совпадают: правя одно, править и другое (`BUN_VERSION` — ещё и с CI и `@docker/*`). Ставят: пакеты (git, make, curl, unzip, gnupg, iproute, клиент ssh); Docker Engine с Compose и buildx из download.docker.com — ключ репозитория сверяется по отпечатку (Ubuntu `9DC8…CD88`, Fedora `060A…9F35`), нужен Docker 25 и новее (`start_interval` в healthcheck); на Fedora — ещё `iptables-nft`: на минимальной системе `docker-ce` тянет `iptables-legacy`, а рядом с firewalld (nftables) правила должны быть в nft; Bun `BUN_VERSION` в `/usr/local/bin` — zip релиза GitHub по `SHASUMS256.txt`, без AVX2 — `baseline`, не `~/.bun`: в неинтерактивный SSH деплоя `.bashrc` не читается, а `/usr/local/bin` в `PATH` есть. По умолчанию — сервер: пользователь `deploy` (`--user`; создаётся с паролем `*` — вход только по ключу, `!` sshd без PAM считает блокировкой) в группе `docker`; ключ GitHub Actions — `--key "ssh-ed25519 …"`, иначе пара создаётся на месте (комментарий `a-sharapov-deploy@<хост>`): открытый — в `authorized_keys` (на Fedora — `restorecon`), закрытый печатается один раз и на сервере не остаётся, повторный запуск видит метку и новую пару не создаёт; порты 80/tcp, 443/tcp, 443/udp — в ufw или firewalld, если они включены; предупреждения о занятых 80/443 (старый nginx) и о памяти (< 2 ГБ с подкачкой — сборке web нужно ~1.5 ГБ). **Swap** (просьба владельца: серверу не дают больше памяти, а сборка web в ~1.5 ГБ на 1–2 ГБ без подкачки падала): `--swap SIZE` (2G по умолчанию, `0` — не создавать) — `/swapfile`, только если в системе нет никакого swap (на Fedora обычно уже есть zram — тогда пропуск) и на `/` хватает места с запасом 1 ГБ; уже лежащий, но выключенный `/swapfile` не трогается. На btrfs — `btrfs filesystem mkswapfile` (сам ставит NOCOW), иначе `fallocate` (не вышло — `dd`) и `mkswap`; права 600, на Fedora — `restorecon`. Сначала `swapon` и только потом строка в `/etc/fstab` (без дублей) и `vm.swappiness=10` в `/etc/sysctl.d/99-swap.conf`; не включился — файл удаляется, `fstab` не тронут. `sysctl` при отказе возвращает 0, поэтому применённость проверяется чтением `/proc/sys/vm/swappiness`. Проверялось в непривилегированных контейнерах (`swapon` там не может задеть хост): `swapon --show` видит swap хоста (zram) — ветки «нет swap» и «включился» — через заглушку `swapon` в `/usr/local/sbin`; синтаксис `mkswapfile --size 64M` — на btrfs хоста без включения. Само включение на настоящем ядре здесь не проверить — только на сервере. В конце — **таблица для окружения `production`** (просьба владельца): `DEPLOY_HOST` (`--host`, иначе адрес исходящего маршрута `ip route get`; частный адрес помечается), `DEPLOY_PORT` (`sshd -T`), `DEPLOY_USER`, `DEPLOY_PATH` (`--path`, иначе `~deploy/a-sharapov`), `DEPLOY_URL` (`--domain`, `a-sharapov.com`), `DEPLOY_HOST_KEY` (`/etc/ssh/ssh_host_ed25519_key.pub` и отпечаток), секрет `DEPLOY_SSH_KEY`. Таблица без правой рамки: `printf` в C-локали считает ширину кириллицы в байтах, поэтому колонка «Вид» выровнена пробелами в самих строках. `--local` — рабочая машина: только пакеты, Docker и Bun, пользователь `sudo` — в группу `docker`, без таблицы. Готовое пропускается: стоящий Docker не трогается, если это не обёртка podman, есть compose и версия 25+. Без systemd (контейнер) dockerd не включается — предупреждение. Разбор вывода команд — без `grep -q` и `awk … exit` в конвейерах: при `pipefail` ранний выход читателя даёт SIGPIPE писателю и ложный результат, а `dpkg-query` по отсутствующим пакетам возвращает 1 — так молча обрывалась установка на Ubuntu.
- Первый деплой на новый сервер: скрипт подготовки (см. выше), DNS на сервер. Запустить Deploy: код приедет, `server.sh` остановится на «нет .env» — стек не тронут; на сервере `make dot-env ENV=prod`, вписать `TG_TOKEN` (права 600 ставит сам генератор); старый стек (nginx + certbot) остановить — порты 80/443; снова Deploy.
- Репетиция деплоя без сервера: «сервер» — контейнер `docker:28-dind` (`--privileged`, свой демон, порты 80/443 внутри) с bash, git, make, curl и Bun (бинарь из `oven/bun:1.4.4-alpine` + `libstdc++`, `libgcc`); bundle — `docker cp`, `receive.sh` — `docker exec -i … bash -s -- /opt/a-sharapov <sha> master`, как по SSH; домен `a-sharapov.localhost` (Caddy сам выдаёт локальный сертификат на `*.localhost`), `TG_TOKEN` — заглушка (бот без Telegram только сохраняет). Боевой токен в репетицию не подставлять. Шаги самого `deploy.yml` — дословно (текст `run:` из YAML через `Bun.YAML`, каждый шаг — файлом, как в Actions: из heredoc `ssh` съедал бы остаток скрипта) в отдельном контейнере-«раннере» (alpine + bash, git, openssh-client: `ssh` берёт конфиг из домашнего каталога по passwd, не по `$HOME`, — на хосте шаг затронул бы `~/.ssh`), сервер — sshd и пользователь `deploy` в группе `docker`. В `/tmp` DinD `docker cp` не пишет (отдельное монтирование) — файлы через stdin. Результаты (октябрь 2026): без `.env` — остановка до контейнеров; первый деплой — все сиды и smoke; релиз с `pages.json` и кодом — сид только `pages`; сломанный `/api/health` — откат на прошлый коммит, `.deploy/deployed` прежний; от `deploy` по SSH — `pb_migrations` (root после старта CMS) возвращены, деплой зелёный. Пока пересоздаётся web, ~1.2 с proxy отвечает 502 со страницей «Сайт обновляется» (`handle_errors`), `fallback.js` сам перезагрузит её; остальные запросы — 200. Скрипты подготовки репетируются так же (октябрь 2026): чистые `ubuntu:24.04` и `fedora:44` с `--privileged` и томом на `/var/lib/docker`, sshd ставит обвязка (`ssh-keygen -A`), скрипт — через stdin, как на сервере без репозитория, дважды; dockerd — вручную. Перед ним — подготовка cgroup v2, как в `docker:dind` (процессы — в `/sys/fs/cgroup/init`, контроллеры — в `cgroup.subtree_control`), иначе `runc`: «cannot enter cgroupv2 … in threaded mode»; `iptables-legacy` в контейнере не работает вовсе (нет `/lib/modules`) — так и нашёлся `iptables-nft` для Fedora. Дальше — дословно по таблице: `known_hosts` из `DEPLOY_HOST` и `DEPLOY_HOST_KEY`, вход по созданному скриптом (Ubuntu) или переданному `--key` (Fedora) ключу, receive и деплой. Результат на обеих: повторный запуск всё пропускает и новую пару не создаёт, `PATH` неинтерактивного SSH с `/usr/local/bin`, без `.env` — остановка, с `.env` — сборка, все сиды, smoke, страницы 200, файлы кэша в томе `web_cache`.

## Ловушки

- **Не называть параметр `$` в `.svelte` / `.svelte.ts`**: компилятор переписывает `===` в `$.strict_equals` и ломает рантайм. Использовать `_`.
- **Каждую процедурную модель проверять на вывернутые части** (обход граней / нормали внутрь): тест «нормали наружу» для генераторов (`__tests__/viewer/svg.test.ts`) и поворотный стол `/dev/model?name=…`. Жёлоб вместо выпуклости или тёмная деталь на свету — изнанка. Не маскировать через `DoubleSide`.
- **Металл — только платина** (`PLATINUM`), никакого золота; фарфор — просто белый.
- **Фарфор чашки и блюдца** (`models/porcelain.ts`, тест `porcelain.test.ts`): основа — `MeshPhysicalNodeMaterial` на общем окружении сцены (рассеянный свет и объём — как у остальных предметов), тонкий лак (clearcoat 0.5, шероховатость 0.07 — чёткие блики прямого света с тенями) и слой глазури добавкой в `emissiveNode`: отражение своей студии (`bakeStudios` — комната с окнами по направлениям `WINDOWS`, у ключевого — переплёт, ночью — холодные окна и абажур), френель Шлика (F0 0.04 = ior 1.5), день и ночь смешиваются по `mood.night` (`GLAZE_LEVEL`). Свою карту в `material.envMap` не ставить: она заменяет общее окружение и для рассеянного света — днём фарфор пересвечивался и терял объём, ночью рыжел от одной тёплой лампы. Неглазурованное кольцо ножки (бисквит: матовее, без лака) — маски по высоте профиля (`CUP_ZONES`, `SAUCER_ZONES`). Просвечивание тонкой стенки ночью — от лампы вручную, без теней (`_translucency`: в модели SSS three тень от собственной задней стенки гасит свечение лицевой). Пересвет проверять замером: доля пикселей > 245 на чашке не выше прежней (день — общий план, CV и три крупных ракурса `?cam`); альбедо `#e7e5e1` подобрано под полный ключевой свет (импост гобо с чашки убран).
- Дневной свет — три окна **перед** сценой (`Lights.svelte`, `_WINDOWS`): тени уходят от зрителя и перекрываются полутенями разной плотности. Ключевое справа спереди (`share` 0.6), второе слева (0.17), потолок (0.12); у второстепенных меньше выборок PCSS и карта 1024. Вечером главный свет — лампа за визиткой, её тени по-прежнему ложатся вперёд.
- Тон стола и фона днём — один серый: стол `#cacaca`, фон `#d4d4d4` (`mood.ts`, `--background`/`--ambient` в `theme.css`). Свет меняет освещённость стола — подгонять фон по замеру кадра, иначе проступает горизонт.
- Тени — PCSS на TSL (`Scene/soft-shadows.ts`, `pcssFilter`) через `shadow.filterNode`: `lightSize` — размер источника в текселях карты, `perspective` — для прожектора (глубина линеаризуется по near/far его камеры). Выборок 32: при меньшем числе широкая полутень (> ~80) расползается до исчезновения тени.
- Стол матовый: отражение — размытый ореол у основания предметов, а не зеркало (высота отражённой точки по глубине отражения; затухание и размытие с высотой — `reflectionFalloff`, `reflectionFar` в `mood.ts`; френель ослаблен).
- Ночь: свет тёплый (лампа, заполняющий), настроение холодное — сине-серые фон, стол, рассеянный и лунный свет из окон. Огней боке на заднем плане нет (убраны по просьбе), только пылинки: тёплые и ярче в луче лампы, вне луча — холодные и почти прозрачные (`unlit` в `Bokeh/nodes.ts`). Свет лампы на столе — 540 (было 900).
- Перелёт камеры стартует в момент клика: целевой план берётся из `data-shot` ссылки (`Viewer._predict`), после подмены страницы цель уточняется на лету без перезапуска, контент проявляется только когда страница уже в DOM (`ready`). Ссылкам на страницы со сценой нужен `data-shot`. Кривая — cubic-bezier(0.4, 0, 0.1, 1): быстрая атака, длинное торможение. Работа камеры (`shots.ts`, `camera-rig.svelte.ts`, тест `camera.test.ts`): облёт — смещение камеры вокруг цели взгляда поворотом по вертикали на `SWING`·sin(πt) (0.24 рад; туда — в одну сторону, обратно на общий план — в другую, между страницами — половина), наклон — один плавный, к центру дуги, не больше 0.8° (`arcRoll`; крен по ускорению перекладывался туда-сюда: путь — S-кривая, а камера сама поворачивается); фокус переводится позже камеры (`shotCue`: 0.25…0.9 хода) с «передышкой» — посреди пути зона резкости уже, боке больше (`_BREATH`), к 0.8 хода всё сходится; при подаче предмета фокус ведёт сам предмет (`movers`, `_follow`) и к концу садится на план. Объективы по планам: общий план 40°, CV, «Услуги» и 404 — 24° (~55 мм: перспектива почти без искажений, высокие предметы сверху не «разъезжаются»), «Контакты» — 40°: маршрут броска и раскрытие листа подобраны под камеру на 36 см (на 24° она на 61 см, и улетающий самолётик в момент подмены ещё в кадре) — `LENSES` в `staging.ts`. Раскладка соседей (`ROOM`) считается с высотой камеры при 40° (`_LAYOUT_HALF_FOV`) — одобренная раскладка не меняется. Вступления нет (убрано по просьбе владельца): на главной камера с первого кадра, ещё под лоадером, стоит на общем плане — визитка по центру и в фокусе — и после загрузки не трогается (`_waiting` в `camera-rig` и первый план `intro` с нулевой длительностью; без неё «перелёт» на то же место дал бы облёт `SWING`), контент проявляется через ~0.3 с после `moving`. Раньше камера стояла низко у кромки чашки и за 4.2 с отъезжала в общий план (`OPENING`, `openingAt` — в истории git). На других страницах первая загрузка — как прежде: перелёт с дальнего плана (`establishingPose`), при `prefers-reduced-motion` — сразу на месте.
- Радиальное боке общего плана — подмена глубины на входе DOF (`postfx.svelte.ts`): края кадра «отодвигаются» от плоскости фокуса. У DOF three боке крупнее, чем у pmndrs при том же `bokehScale` — множитель `_BOKEH_SCALE`; BloomNode суммирует пять уровней — сила ×0.2.
- `sweepFrom({ squareness })` — сечение-суперэллипс: 2 — эллипс, 6–10 — прямоугольный пруток (подставка визитки 1.0 × 1.4 мм).
- Токарные профили из Безье: `divisions` 3–4 на сегмент — по умолчанию 12 и чашка весит 200+ тыс. треугольников.
- Движущийся предмет, отбрасывающий тень, должен ставить `rig.shadowsDirty = true` — в своей задаче (`useTask`), до рендера кадра: по этому флагу будятся карты теней, и он же снимает неподвижность кадра (`rig.still`). Предмет, который двигается без флага, в покое оставит за собой старые AO и отражение.
- **Рендер — `WebGPURenderer` + TSL** (`three/webgpu`, `three/tsl`): без WebGPU сам переходит на WebGL2-бэкенд. Шейдеры — только TSL-ноды (`colorNode`, `emissiveNode`, `outputNode`, `filterNode`…), не GLSL-строки и не `onBeforeCompile`. Скилл — `webgpu-threejs-tsl`.
- У node-материалов туман включён по умолчанию: частицам и пару — `fog: false`, иначе дальние огни гаснут до цвета фона. Детали без UV, но с `bumpMap`, — `projectedUv` из `svg.ts`.
- Окружение (`PMREMGenerator` из `three/webgpu`) запекается только после `await renderer.init()`.
- **Текстуру из файла не помечать `needsUpdate` до загрузки картинки** (и не `clone()` её раньше — `copy()` сам ставит `needsUpdate`): WebGPU падает `Cannot read properties of null (reading 'complete')`, WebGL молча пропускает. `useWood` создаёт пустую `Texture` и подставляет `source` в `then`.

Почта на обороте — свой сплошной конверт (`_ENVELOPE`): у `mail.svg` со страницы контактов конверт белый, на бумаге от него остаётся треугольник. Бумага оборота приглушена (`_BACK_TONE`) и матовее — иначе развёрнутая к окнам визитка уходит за порог bloom и светится; холст зеркальный: UV обеих крышек одинаковые, крышки визитки разделены на группы материала 0 (лицо) и 2 (оборот). Строки контактов кликабельны по UV (`linkAt`), строка под курсором красная; клик мимо строк, мимо визитки или Esc — обратно в подставку. Страница контактов — по меню; DOM-копия визитки ведёт туда же. Полёт — `Tween` с `cubicOut` в обе стороны (отклик сразу, разворот посреди пути — от текущей точки): вверх над подставкой, затем вперёд; поворот оборотом — только в полёте (`_SPIN`). Наведение держится, пока визитка развёрнута (ракурс не меняется). В воздухе (`_AIRBORNE`) визитка не отбрасывает тень: широкая полутень PCSS на повёрнутой к свету визитке затеняет её саму полосами. Оборот — без тиснения и со сдвигом mip-уровня (`bias`): иначе мелкий текст мылится.
- **Пасхалка — сбой и пикселизация** (только 3D): пять смен состояния визитки подряд (подлёт и возврат любым способом — клик, клик мимо, Esc; между соседними не дольше `GLITCH.gap` = 2 с) — `tapCard` в `Scene/glitch.ts` (чистая функция с цепочкой, тест `glitch.test.ts`), считает `$effect` на `flipped` в `BusinessCard.svelte`; клик по ссылке на обороте состояние не меняет и не считается. Эффект — 5.5 с по графику `glitchAt`: сразу сдвиг полос и расслоение каналов, мозаика растёт до 26 CSS-пикселей к ~3.4 с и держится, к концу всё собирается. Постобработка: стадия перед `lensColor` (`lens/glitch.ts`, `glitchWarp`) — координата выборки кадра до bloom квантуется в блоки, по полосам и плиткам сдвигается по хэшу (`hash` TSL берёт целое зерно — номер полосы, плитки и ступени времени `GLITCH.step` = 70 мс), каналы R/B разводятся; `lensColor` получил необязательные `at` и `split` (без них — прежняя картинка: аберрация берёт R/B из текстуры по своей координате, и подмена одного центра развела бы каналы); в конце `glitchTone` — лёгкая постеризация и строки развёртки. Uniform'ы `glitch`, `pixel`, `seed` ставит `_glitch` в `_tune`, он же переключает `viewer.glitch` → `html[data-glitch]` (`Viewer.svelte`): шапка и подвал дёргаются со сдвигом и цветной окантовкой (`chrome-glitch` в `Html.css`). Без вспышек всего экрана (светочувствительность); при reduced motion — только мягкая пикселизация без сбоев и без дёрганья интерфейса. В упрощённой версии сцены нет — нет и пасхалки.
- Нажатие на визитку — только лёгкое сжатие, без сдвига: она опирается на упор и стоит на основании, сдвиг назад или вниз проводит её сквозь подставку. Наведение — сначала подъём из гнезда (`h · 1.6` см), поворот, наклон, крен и выдвижение вперёд — только после него (`_SWING`: с 0.35 хода), иначе низ визитки проходит сквозь передний упор (зазор до него меньше миллиметра, поворот по курсу сразу толкает правую половину края вперёд, крен её опускает); недолёт пружины ниже нуля отрезан (`Math.max(0, …)`) — с ним визитка уходила за заднюю перекладину. Проверено пересечением визитки с треугольниками подставки по всему ходу: с 0.35 зазор ≥ 0.5 мм, касание только при скольжении вверх вдоль упора (концы боковых проволок сходятся в плоскости визитки уже в покое — не в счёт). Наведение считается по месту визитки в покое: невидимая мишень `cardSpot` (та же геометрия, `visible={false}` — луч three видимость не проверяет) плюс сама визитка (`over.card || over.spot`); прежде курсор у нижнего края терял визитку, когда она поднималась, она опускалась обратно под курсор — петля (38 переключений на 80 шевелений). Щелчок раздаётся всем объектам под курсором, поэтому одно нажатие обрабатывается один раз (`handled` — исходное событие, его же помечает `missed`), иначе мишень сразу закрывала только что открытую визитку. После закрытия движение над мишенью или визиткой снова наводит (`_hoverIn`).

Фактура — только рельефом, «не заметна, но ощущается»: тайл `_coating` (value-noise с клеткой 0.3–0.075 мм и пиксельное зерно) в `bumpMap` обеих сторон с силой 0.6 (`BusinessCard.svelte`, гаснет в листе вместе с печатью); ночью свет лампы и чтения идёт вскользь и рельеф виден сильнее — подбирать силу по вечернему кадру. Взятый из середины или снизу сначала выезжает вбок из-под лежащих сверху (`SLIDES`, первые `SLIDE_SHARE` пути), затем они оседают на его место (`pileLift`); возвращаясь, он въезжает обратно, а верхние перед этим приподнимаются. Смена актёра без движения камеры — не короче `_ACTOR_SWAP` (резюме, скетчбук, планшет и самолётик — `ACTOR_SECONDS`, туда и обратно по-своему: резюме и планшет 2.2 / 2 с — чтобы ручка и стилус успели спокойно лечь); перенос — своя кривая `carryEase` (`staging.ts`), не быстрая атака камеры. Соседи на столе переезжают в первой половине перелёта (`roomShare`). При смене страницы (поданы оба актёра) раскладку задаёт тот, кто дальше прошёл свой перенос (`_roomWeights`: доля `carryTravel⁶`), — соседи едут из одной раскладки прямо в другую, пока уходящий уже поднялся, а входящий ещё не опустился; прежняя сумма сдвигов уводила их в «сумму» раскладок — стопка проезжала сквозь стакан, визитка сквозь самолётик. Обложка скетчбука — обсидиан (глубокий чёрный с лаковым отблеском), резинка — тёмно-серая; на столе она лежит не по линейке (по просьбе владельца): боковая волна `_wobble` — три синусоиды с некратными частотами, −0.6…+1.6 мм наружу (до обложки 2.5 мм), гаснет к загибам за обложку; у `sweepFrom` для этого опция `shift(t, point)` — сдвиг оси в плане по нормали, пара к `lift`; закрытая форма (морф) без волны — натянутая резинка прямая. - GTAO и шумоподавление берут настоящие нормали из MRT прохода сцены: восстановленные из глубины на столе, видимом вскользь, дают полосы. Вторые выходы MRT по умолчанию пишутся **без смешивания** (блендинг берётся из MRT прохода, не материала): прозрачным слоям — `keepSceneNormals` (`Scene/mrt.ts`), иначе на месте частиц и пара тёмные пятна AO.
- Вся цепочка AO (GTAO и оба прохода шумоподавления) — в разрешении CSS-пикселей (`1 / pixelRatio`, низкий уровень — половина буфера): каждый проход шумоподавления — в свою `rtt(..., { resolutionScale })`, иначе `convertToTexture` берёт полное разрешение буфера, а последний проход считается прямо в итоговом шейдере на каждый пиксель. При плотности 1.75 полный кадр — 9.4 мс GPU вместо 12.5 (главная, 2520×1575); `?fx=aofull` — прежнее полное разрешение для сравнения.
- **Видеопамять** (693 → 518 МБ при 1440 × 900 × 1.75; почти всё растёт с числом пикселей): промежуточные цели постобработки — без буфера глубины (`_FLAT` = `{ depthBuffer: false }` у `rtt` и `convertToTexture`: по умолчанию у каждой полноэкранной цели своя глубина на 15 МБ); вход DOF — текстура TRAA (`_texture(jittered)`: `convertToTexture` не узнаёт `TRAANode` и копировал кадр в ещё одну полноэкранную цель); размытие CoC в DOF и выходы шумоподавления AO — `RedFormat` (читается только `.r`, у входа GTAO и так один канал — результат тот же); холст без глубины (`depth: false`: по нему рисуется только итоговый квадрат); `PMREMGenerator` окружения освобождается сразу после запекания. Скорость в MRT как RG16F нельзя: у формата нет альфы, а прозрачные слои пишут её со смешиванием — пайплайны пара и пылинок не собираются.
- Замер GPU-времени кадра (`scratchpad`-скрипты, `__asDebug.pipeline`): цикл приложения остановить и перед каждым `pipeline.render()` сдвигать кадр нод (`renderer._nodes.nodeFrame.update()`, `renderer.info.frame = frameId`) — иначе проходы постобработки (обновление раз за кадр) пропускаются и цифры занижены вчетверо. Четыре воркера: **пиксели** (`pixel-jobs.ts`, `fillPixels`: текстура создаётся нулевой и заполняется ответом, задания с одинаковым ключом сливаются) — шум, рельеф бумаги, гобо, 3D-шум пара, две таблицы грейда; **страницы скетчбука** (`sketches/page-textures.ts`); **раскладки** (`rooms.ts`); **геометрия** (`models/geometry-jobs.ts`: рецепты `sketchbook-geometry.ts` и `pen-holder-geometry.ts` в `geometry-recipes.ts`, SVG разбирается на главном потоке — `SVGLoader` нужен `DOMParser`, — пути уходят в воркер через `Path.toJSON`, геометрия возвращается массивами атрибутов с передачей буферов, `geometry-pack.ts`). Воркер геометрии запускается в начале `Scene.svelte` (`prepareGeometry`), скетчбук и стакан монтируются по готовности (`modeled`), а `loaded` ждёт её — иначе их материалы собирались бы уже на глазах у посетителя; ответ примерно в половине загрузок приходит уже после первого кадра (главный поток занят им ~2 с: 2.1–2.2 с против 0.58 с), и стакан со скетчбуком собираются вторым заходом — раньше `loaded` ждал только сам ответ, и эта сборка шла под слоганом лоадера, теперь прогрев рига ждёт и её (`pipelines.pending`, см. «Пайплайны WebGPU на загрузке»); `geometryOf` без готового ответа (лаборатория, запасной путь) строит синхронно. Результаты воркеров совпадают с главным потоком побайтно (пиксели, страницы, атрибуты геометрии; раскладки — по JSON). Ловушки: импорт из `three` в воркере тянет ~90 КБ (`toHalfFloat` — из `three/src/extras/DataUtils.js`, воркер пикселей — 7 КБ; воркеру геометрии three нужен — 157 КБ); воркер страниц, запущенный при загрузке, давал задачу ~0.7 с после первого кадра (растр `OffscreenCanvas` в воркере во время сборки шейдеров) и `loaded` +0.7 с — поэтому он запускается только в простое после `settled` и завершается, когда страниц не осталось; в dev воркер, импортирующий three, грузит его модулями без пребандла — секунды, в проде — чанк. Добавляя расчёт в воркер, мерить `gpuinit`-замером (время запроса адаптера и длинные задачи до первого кадра), а не только `loaded`: шум `loaded` между прогонами ~0.1 с.

После загрузки — синхронно, как раньше: обход всех страниц и смена темы новых пайплайнов не собирают (все 127 — при загрузке), а асинхронный пайплайн заменённого материала значил бы пропавший на несколько кадров объект. Прогрев рига ждёт пустую очередь (см. «Фазы загрузки»), старт камеры (`launched`) — тоже. Результат (тот же замер, 3 прогона попеременно): `CrGpuMain` 1.8–1.9 с, задачи ≤ 126 мс, браузер 41–43 кадра/с, пауза ≤ 0.24 с, `loaded` 3.4–3.6 → 2.8–3.0 с; Chrome на двух ядрах (`taskset -c 0,1`) — задачи 0.53–0.6 → 0.18–0.19 с, пауза 0.77–0.85 → 0.37 с; кадр после `settled` прежний (разница скриншотов на уровне шума двух прогонов одной сборки, и в WebGL2). - Полёт самолётика (`flight.ts`, тест `flight.test.ts`): путь — кубический сплайн по времени (C2: скорость и ускорение без скачков, и на стыках участков) через точки маршрута с ровным шагом ~3 см (`_resample`; неровный шаг даёт выбросы кривизны и рывки крена). Времена точек — по закону энергии `v² = v0² − 2G·Δh − 2·drag·s` (`G` = 50 см/с², «рапид»): после толчка самолётик сам высоту не набирает — на подъёме теряет скорость, на снижении набирает; стартовая скорость подобрана бисекцией, чтобы полёт кончился в срок (`_paceFor`). Ориентация — из движения: нос по скорости, поднятый на угол атаки (растёт при торможении — выравнивание перед касанием); «верх» — по подъёмной силе: крен к центру поворота `atan(a⊥/G)` до `_BANK`, ускорение для крена усреднено по ±0.24 с (крен инертен), знаменатель не меньше 0.6·G (в невесомости верха броска крен иначе скачет). Крен лежащей модели (на законцовке крыла, `PlaneFold.roll`) в полёте снимается и возвращается на остановке; вершины дротика не уходят под стол, складывающийся лист — тоже. Туда (по подаче, `ACTOR_SECONDS.plane[0]` = 2.6 с): толчок вверх по носу, сваливание в верхней точке, раскрытие в воздухе (во всю ширину — когда соседи расступились), лист опускается, покачиваясь, и ложится раньше, чем проявится контент (тест). Обратно — по своим часам (`PLANE_SECONDS.back` = 4.4 с; перелёт камеры его не ждёт, `ACTOR_SECONDS.plane[1]` = 1.6): лист складывается на месте подачи (ось сгиба стоит — нос вправо по кадру, без разворота на месте), толчок вправо, левый вираж с набором высоты за визиткой, планирование вдоль стола за стаканом, разворот к зрителю у левого края (вне общего плана) и заход слева по носу лежащего самолётика: касание, пробег, на остановке он ложится на крыло и доворачивает (~25°). Весь облёт — один левый вираж с прямым плечом: перекладка крена сразу после поворота рвёт крен. Прерванный новым переходом полёт плавно перетекает в новый (`_BLEND` в `Actor.svelte`). Маршруты — `_FORTH`, `_CIRCUIT`, `_ARRIVAL`; зазор до препятствий (`obstacleGap` из `carry.ts`, соседи — по их подаче в тот момент) проверяет тест. **Обратно — два маршрута** (`Actor.svelte` выбирает в момент вылета, `plane.route`): `back` — когда на стол никто не выходит (общий план), `around` — когда подаётся другой предмет (из контактов в CV, «Услуги», 404). Самолётик сидит в обёртке `room-plane`, и при смене страницы весь его путь едет вместе с его местом в раскладке входящего актёра, а стакан — со своим; в раскладках скетчбука и планшета стакан относительно самолётика сдвигается на 4.5–9 см вправо-назад и встаёт прямо на участок «вдоль стола за стаканом» (было: «Контакты → Услуги» −3.6 см, → 404 −4.8, → CV −0.8 — самолётик пролетал сквозь стакан). Один маршрут на все случаи невозможен: на общем плане коридор только между стаканом и низко висящим абажуром лампы (`shade` на высоте ~13 см над `onFrame(4, −9)`), а в раскладках актёров его занимает стакан, зато лампа уезжает вправо. `around` — тот же взлёт без двух последних точек, затем `_CIRCUIT.behind` (глубже, ~17 см за визиткой, в обход всех положений стакана) и хвост `turn` с четвёртой точки — один левый вираж без перекладки крена; сопротивление `aroundDrag` 1 (длинный путь с прежним сопротивлением требовал сильнее толчка, взлёт уходил вперёд и при «Контакты → 404» задевал визитку, которая в этот момент проезжает в новую раскладку). Броска это не касается: его вылет идёт в раскладке контактов. Тест облёта — в раскладке перехода (`roomGap` из `carry.ts`: смесь раскладок по `roomFor`, как в `Room.svelte`, плюс сдвиг самой обёртки самолётика), подача — `carryEase(t / ACTOR_SECONDS[actor][0])`: длительность перехода из контактов задают актёры (камера — 1.2–1.8 с). Запасы: CV и «Услуги» +1.3 см, 404 −0.95 (допуск −1: сферы препятствий с запасом) — узкое место там не стакан, а визитка, проезжающая под взлётом, пока обёртка самолётика съезжает на ~9 см в воздухе; до инструментов из стакана облёт держит 2.7–5 см (прежний маршрут — 1.4–2.7).

Текстуры — RGBA без мипов (RedFormat с мипами в WebGPU читался как белая заглушка).
- **Объёмный свет** (`volumetric.ts`, в конвейере после AO, до TRAA, половинное разрешение, ~0.28 мс GPU): свой ray-march на TSL (20 шагов, сдвиг по пикселю и кадру — сглаживает TRAA), тени — сырая глубина карт (`light.shadow.map.depthTexture` подставляется в `TextureNode` вместо заглушки, когда карта появится; `GodraysNode` three не подходит — только точечный и направленный свет и аппаратное сравнение, а PCSS читает карты как сырую глубину). Днём — лучи ключевого окна (`mood.shafts`), ночью — конус лампы (`mood.beam`, свой конус 0.42…0.62 рад уже света 0.9 — у широкого конуса без края формы луча нет). Окна перед сценой, свет уходит от зрителя: весь воздух освещён, и без маски была ровная молочная завеса — поэтому в воздухе свет проходит только сквозь «жалюзи» (`VOLUME.panes` — семь полос по v пространства света: эти пласты почти параллельны взгляду, луч зрения идёт в них долго, полосы видны; полосы по u — вертикальные стенки под 45°, пересекаются поровну, узора нет). Дымка — у стола (`height` 12 см), гаснет ближе 20–45 см от камеры (иначе завеса у объектива) и дальше 110–220 см от центра. На страницах лучи — 35 % (`_SHAFTS_PAGE`). Свет — по имени: `keyWindow` (первое окно), `lampSpot`.
- **Звук** (`@UX/Sound`, `@UX/SoundSwitcher`, `@Viewer/Sound/SoundCues.svelte`, тест `__tests__/sound`): только процедурный WebAudio, выключен по умолчанию; AudioContext — только по жесту: кнопка в шапке или, если звук включали раньше (`AS_sound`), первый `pointerdown`/`keydown`. Мастер: +5 dB → лимитер (−12 dB, 8:1), при скрытой вкладке — затухание и `suspend`; внешних запросов нет. События — по прогрессу, не по скорости (на плавном торможении `carryEase` порог скорости опаздывает на 0.1–0.2 с): актёры — по концам `carryTravel` (0.005/0.995), инструменты — по `toolProgress` (дома — керамика, на столе — стук), визитка — пороги `rig.card.flip`, обложка — `SKETCH_TIMELINE`, экран — 0.68, лампа — `rig.lamp.clicks`, самолётик — локальная скорость `actor-plane` относительно `room-plane` (повтор запуска не раньше 0.8 с). Проверка без ушей — рендер `playCue` в OfflineAudioContext и журнал `__asSound.state.log` (dev).
- **Ночной фон** (`AMBIENCE.night`, `createAmbience`, тест `cues.test.ts`): ночью комната не тише дня (запись комнаты −34.5 dB против прежних −39.5), но глуше (срез 3 кГц против 9), и в ней слышны часы и лампа — тихо, на 6 dB ниже первого варианта (просьба владельца). Часы — запись CC0 `clock.mp3` (обработка — `LICENSES.md`), за кадром слева (`CLOCK_PAN`), петля `CLOCK_LOOP` по схеме комнаты (по 0.5 с повтора по краям), только ночью (днём их «заглушает» улица, `clock` дня — 0); грузится с остальными звуками, до загрузки часов нет. Сначала были процедурные (щелчок → резонансы корпуса → отражения), владелец попросил заменить записью. Выбор — 211192 «small clock in room»: из 24 записей CC0 с freesound ровнее всех (период 1.000 с, разброс 3 мс), сигнал/шум 43 dB, без посторонних звуков, свой хвост комнаты ~0.1 с (417593 — второй щелчок через 0.16 с после каждого удара, 666582 — неровные удары, остальные шумные, быстрые или будильники). Гул лампы — сеть 50 Гц, гудит на 100 Гц с гармониками (`LAMP_HUM`, одна `PeriodicWave`), громкость колышется волной ±25 % (тремоло 0.21 Гц; ±12 % на слух было ровным) и идёт за накалом нити `rig.lamp.power` (разгорается и остывает вместе с ней), панорама и расстояние — по `lampSpot`; на телефоне сцены нет — нет и гула. Уровни сведены рендером в Chrome (OfflineAudioContext, настоящие записи, 12 с, средняя мощность моно): день −48.4 dBFS, ночь была −53.9, стала −48.3 при горящей лампе; выше 200 Гц комната ночью −57.2, гул −67; часы поставлены на тот же 30-мс уровень ударов, что у одобренного синтеза (−55 dBFS, пик −39.5).
- **Записанные звуки** — `web/static/sounds/*.mp3` (CC0, источники и обработка — `LICENSES.md` рядом), манифест `SAMPLE_FILES` и уровни `SAMPLE_CUES` в `@UX/Sound/samples.ts`; грузятся только после включения звука (`loadBank`), нет файла — звучит процедурный голос того же события (синтезом остались свист полёта и тон экрана). MP3 — единственный формат, который `decodeAudioData` декодирует везде (AAC в Firefox на Linux зависит от системы, Opus в Safari ненадёжен); задержку кодера срезает `leadOffset`, петля комнаты — `ROOM_LOOP` (0.5 + 10 с) внутри периодического файла — новый звук для петли готовить так же. Подготовка: моно 48 кГц, срез низов, атака ≤ 3 мс, пик −1.5 dBFS; громкость в сцене — по RMS к соседним событиям (рендер в OfflineAudioContext). Тест сверяет манифест, папку, лицензии и вес (< 400 КБ).
- **Пылинки — суперпозиция**: чёткое ядро ровно в пиксель на любом расстоянии и в любом расфокусе плюс мягкий ореол, как раньше, но прозрачнее (`DUST` в `Bokeh/nodes.ts`: `halo` 0.7, `core` 0.9). Ядро не размывается DOF: пылинка пишет его в отдельный выход MRT прохода сцены `cores` (8 бит, через `keepSceneNormals(material, renderer, { cores })`; у остальных материалов там ноль, тест глубины прячет пылинки за предметами), а после DOF ядра накладываются поверх кадра — `кадр·(1 − a) + ядро` (светлое ночью и тёмная крапинка днём ложатся верно) — до аберрации, смаза и bloom. Спрайт не меньше 3 пикселей, форма ореола пересчитана к прежнему размеру. Лишний выход MRT — ~0.1–0.2 мс GPU прохода сцены.
- **Фон сцены — `scene.backgroundNode`, не `scene.background`** (`Lights.svelte`, uniform цвета): цветом `scene.background` three очищает все выходы MRT, и в выходе ядер там, где нет геометрии, оказывался непрозрачный цвет фона — над горизонтом кадр темнел с резкой границей. Узел фона рисуется отдельной плоскостью и пишет в остальные выходы MRT нули.
- **Воздух** (`wind.ts`, тест `wind.test.ts`): за движущимися предметами (`movers`) остаётся след из «затяжек» в общем кольце (80, шаг пути — половина радиуса предмета, не меньше 3 см; при нехватке перезаписывается самая слабая). Пылинки читают след на GPU (`uniformArray`: сдвиг вдоль скорости и пара встречных вихрей, нормировка на плотность затяжек — у пути ~2 см, к 4 с ноль; без compute — работает и на WebGL2), пар — на CPU (`airAt`, без собственной затяжки чашки). За самолётиком пылинки собираются в шлейф (`WAKE`, `wind.wake` — третий `uniformArray`): затяжки самолётика (через 3 см пути) тянут пылинки поперёк пути к линии следа (окно по длине 6 см, захват 12 см, срез дальше 2–3 захватов; гладкая нормировка `pull / (w + soft)` — доля пути к линии всегда меньше единицы, без перелёта и без излома), проявляется за ~0.5 с и гаснет к 2.6 с. Без рывков на виражах (тест — вторая разность сдвига < 0.12 см/кадр²): направление затяжки — сглаженный курс предмета (`HEADING_LAG` 0.18 с), а не мгновенная скорость; огибающие затяжек (`wakeEnvelope`, `pushEnvelope`) стартуют с нулевой производной — `1 − exp` с ненулевым наклоном давала излом в каждый кадр рождения затяжки (было 0.6 см/кадр², стало 0.06) — пылинки плавно расходятся по местам; то же слагаемое в том же цикле шейдера — несколько операций на частицу и затяжку (455 частиц × 80). Шаг ветра — раз в кадр по `renderer.info.frame` (`wind.step` вызывают и пылинки, и пар). Проверка в браузере — `wind.gustAt`; модуль брать по адресу из `performance.getEntriesByType('resource')`, иначе после HMR (`?t=`) это другая копия.
- **Снос пара** (`Steam/drift.ts`): у каждого уровня струйки смещение и скорость — воздух разгоняет (`coupling`), всплывание тянет назад (`frequency`), всё переносится вверх со скоростью подъёма пара, у глади ноль; снос мягко ограничен (`driftReach`, tanh), размах змейки в сносе ослабевает (`DRIFT_CALM` в `axis.ts`) — иначе струйка выходит из цилиндра ray-march. Когда вокруг ничего не движется, снос не считается.
- **Изгиб бумаги** (`paper-bend.ts`, тест `paper-bend.test.ts`): сдвиг вершин в `positionNode` с поправкой нормалей (`normalLocal.assign`, как скиннинг three) — тени его повторяют (проход теней берёт `positionNode`), скорость в MRT сдвиг не учитывает (`_settledVelocity`, в смаз изгиб не попадает). Плоские детали нарезаются плоскостями (`sliceGeometry`, морфы тоже): у крышек экструзии нет промежуточных вершин. Резюме провисает по длинной стороне при переносе (`SAG`: ~3.4 мм, инерция по вертикальному ускорению, край не ниже стола; при посадке края касаются раньше центра и подскакивают на ~1 мм за 0.5 с — `SAG.kick`; на скорости передний край приподнят), скетчбук — отставание свободного края обложки при развороте (`FLEX`, в осях половины книги; не проходит сквозь стол и закрытую половину) и веер блока до 3 мм (`FLEX.fan`). В покое изгиб ровно 0 — лицо совпадает с DOM-листом; пока изгиб не успокоился, модель ставит `rig.shadowsDirty`.
- **Реестр движущихся предметов** (`movers.ts`, задача `movers`): мировая позиция, скорость (см/с) и радиус актёров, инструментов, визитки, чашки (`cup`) и стакана (`penHolder`) — для звука и воздуха. У обёрток `room-*` мировая позиция — только сдвиг раскладки, брать группы самих моделей.
- **Страница с тем же планом во время доигрывающего перелёта** (CV → «Политика» по ссылке в подвале, оба — план `resume`): `settled` наступает на 0.82 хода, а риг видит, что перелёт к тому же плану ещё идёт, и не перезапускает его — признак показа контента уже израсходован, фаза навсегда `leaving`. Теперь в этом случае риг снова взводит показ (`reveal = true`), и доигрывающий перелёт сам переводит фазу в `settled`.
- Локально не использовать боевой `TG_TOKEN`: polling конфликтует с продакшен-ботом.
